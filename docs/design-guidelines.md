## 1. 색상 시스템

색은 **계열이 아니라 역할로** 관리한다(초록이 배경·텍스트·포인트를 겸하고, 흑백이 텍스트·배경을 겸하기 때문).
아래 표의 hex 가 canonical 이며, **신규 코드는 이 값만 쓴다.**

### 1.1 역할별 canonical

| 역할 | 용도 | hex | 비고 |
|---|---|---|---|
| **배경 · 페이지** | 앱/페이지 배경, 노치 base | `#FFFCEF` | 크림. theme-color·manifest·`:root` base 동일 |
| 배경 · 카드/시트/탭바 | 떠 있는 면 | `#FFFFFF` | |
| 배경 · 보조 면 (GREEN-300/100) | 연초록 패널 | `#C5D89D` / `#ECF6D8` | 다크 텍스트 얹기 (7.9 / 10.4:1) |
| 배경 · 베이지 서브 | 구분 면 | `#F6F0D7` | |
| **텍스트 · 주 (INK)** | 본문/제목/아이콘 | `#2C3930` | 다크그린(니어블랙). 크림 위 **11.8:1 AAA** |
| 텍스트 · 보조 (INK-muted) | 캡션/메타 | `#60655C` | 크림 위 **5.8:1 AA** ✅ (구 `#8D8D8D` 3.2:1 대체) |
| 텍스트 · 비활성 | 비선택/비활성 상태 | `#B4B4B4` | 의도적 de-emphasis (본문 대비 미적용) |
| 텍스트 · 진초록 강조 (GREEN-700) | 링크성/강조 | `#5B6B38` | 크림 위 **5.7:1 AA** ✅ |
| 텍스트 · 반전 | 다크 버튼 위 글자 | `#FFFCEF` | |
| **포인트 · 버튼/강조 (GREEN-700)** | 고대비 CTA·텍스트 | `#5B6B38` | 흰 글자 **5.8:1** / 크림 위 **5.7:1** ✅ (텍스트·버튼은 이걸로) |
| 포인트 · 올리브 면 (GREEN-500) | 마커/칩/데코 채움 | `#788F4A` | ⚠️ **데코 전용 — 텍스트 금지** (흰·크림 모두 ~3.5:1, 어떤 크림으로도 4.5:1 불가) |
| **에러 · 주 (ERROR)** | 에러 텍스트·삭제 버튼 | `#DC2626` | 크림 위 **4.7** / 흰 글자 **4.8:1** ✅ |
| 에러 · 면 (ERROR-surface) | 경고 배너·상태 배지 바탕 | `#FEF7F7` | ERROR 글자 **4.57:1** ✅. ⚠️ 더 진한 분홍은 못 쓴다 — `#FDE7E7` 은 4.08:1 로 미달이고, ERROR 보다 어두운 빨강이 팔레트에 없어 글자로 만회할 수 없다 |
| 즐겨찾기 · 좋아요 | 하트(like) | `#FF4D6D` | 로즈-핑크. **에러와 별개 의미** — 합치지 않음 |
| 캘린더 · 일요일 | 주말 accent | `#FF8080` | 에러 아님(주말 관례색) |
| **액센트 · 골드** | 프리미엄/등급 | `#E7BD5B` · `#DDBF68` | PlanCard·Profile |
| **줄기 · 갈색 (BARK)** | 동선 경로선 | `#7A5C3A` | 나무를 잇는 선 전용. **L\*41 = GREEN-700(43)과 같은 밝기 단** — 초록 옆에서 한쪽만 튀지 않는다. 선·데코 전용이고 텍스트로는 쓰지 않는다(크림 위 6.0:1 이라 대비는 되지만, 초록 텍스트 자리는 GREEN-700 하나로 유지) |

### GREEN 4단계 스케일 (확정 — 앱 아이콘 앵커)

초록은 **4단계로 단순화**했고, 중간·진한 톤(500·700)은 **앱 아이콘(`public/apple-touch-icon.jpg`)에서 직접 뽑아** UI와 런처 아이콘 톤을 일치시켰다.

| 단계 | 값 | 출처 | 역할 (대비가 정함) |
|---|---|---|---|
| GREEN-100 | `#ECF6D8` | — | 밝은 면 (다크 텍스트 10.4:1) |
| GREEN-300 | `#C5D89D` | — | 연초록 패널/칩 (다크 텍스트 7.9:1) |
| **GREEN-500** | `#788F4A` | **아이콘 배경** | 중간 데코/보더 — **작은 텍스트 금지** (~3.5:1) |
| **GREEN-700** | `#5B6B38` | **아이콘 그림자** | 텍스트·버튼 — 흰글자 5.8 / 크림 위 5.7:1 ✅ |

- **밝기 램프:** L* 95 → 84 → 56 → 43. 100/300 = 배경(다크 텍스트 얹기), 500 = 중간 채움(텍스트 X), 700 = 텍스트/버튼(흰·크림 글자).
- **왜 500엔 텍스트를 못 얹나:** `#788F4A`의 휘도(0.24)상 밝은 배경 대비 천장이 **3.6:1**(순수 흰색 기준)이라, 크림을 아무리 조정해도 4.5:1이 안 나온다. 크림 위 초록 텍스트가 필요하면 **무조건 700**.
- 눈대중 변형 40여 종(`#8DA071` `#879B54` `#7F9648` `#9CAB84` 등)은 전부 이 4단계로 접었다(브랜치 `refactor/greenPaletteUnify`).

> 피그마 팔레트 참고값(정리 전): `200 #F6F0D7` `800 #2C3930` (node `46:218`). ⚠️ **main `tailwind.config.ts` 의 `pictree` 토큰은 아직 옛 값**이라 다르다 — Tailwind 토큰화는 이슈 #58에서 별도.

### INK(흑백) 스케일 (확정 — 텍스트 티어)

near-black·회색 텍스트를 **2단계**로 통일했다. 다크 끝단은 하나면 충분하다 — `#20251F`는 "더 진한 강조"가 아니라 blog·premium 모듈의 본문색 드리프트였어서 주 텍스트로 흡수했다(**INK-900 없음**).

| 토큰 | 값 | 역할 | 크림 위 |
|---|---|---|---|
| **INK** | `#2C3930` | 주 텍스트(본문·제목)·아이콘 | 11.8:1 ✅ |
| **INK-muted** | `#60655C` | 보조·캡션·메타 | 5.8:1 ✅ |
| (유지) 비활성 | `#B4B4B4` | 비선택/비활성 상태 텍스트 | 의도적 de-emphasis |

- **핵심:** 구 보조 텍스트 `#8D8D8D`(3.2:1 미달)를 `#60655C`(5.8:1)로 대체 → 크림 위 보조 텍스트가 4.5:1 통과. 회색이 L*≤~48이어야 크림 위 4.5:1이 나온다(`#767676` L50=4.4 미달).
- 아이콘 순수검정 `#111111`도 `#2C3930`(브랜드 다크그린)으로 흡수.
- **LINE(보더/면):** `#D9D9D9`(보더) / `#ECECEC`(옅은 디바이더) — *다음 pass에서 통일 예정.*

### 1.2 규칙

- **눈대중 변형 금지.** 초록은 위 4단계(GREEN-100/300/500/700)만 쓴다. `#8DA071`·`#879B54`·`#7F9648` 같은 근사 올리브를 새로 만들지 않는다.
- **페이지 배경이 크림이 아닌 화면은 `/premium` 하나다.** `linear-gradient(180deg, #ECF6D8, #FFF6D1)` — GREEN-100 에서 따뜻한 크림으로 내려온다. 앱에서 유일하게 무언가를 파는 화면이라 다른 화면과 같은 바닥이면 설정 화면 중 하나로 읽힌다.
  - **새로 만든 값이 아니다.** 즐겨찾기의 '저장한 장소' 정렬 버튼이 쓰던 그라데이션을 되살린 것이다(`1bcf851` 에서 프로필 재디자인과 함께 사라졌다). 아래 끝 `#FFF6D1` 은 canonical 크림(`#FFFCEF`)보다 노랑이 진한 값인데, **이 그라데이션 안에서만** 쓴다 — 단색 면으로 꺼내 쓰지 않는다.
  - INK 대비는 위 끝 10.4:1 · 아래 끝 11.2:1 로 전 구간 AAA 라 글자 색은 평소와 같다.
  - ⚠️ **콘텐츠 배경이 아니라 뒤에 까는 고정 레이어로 넣는다**(`fixed inset-0 -z-10 mx-auto sm:max-w-[390px]`, §3 의 full-bleed 방식). 페이지가 길어 배경에 직접 걸면 2,500px 넘게 늘어나 색이 거의 안 변하고, 기기마다 스크롤 길이가 달라 보이는 색도 달라진다.
- **명암비: 이 앱의 본문은 전부 WCAG '일반 텍스트'다.** 크기 13~15px + 볼드 미사용이라 '대형 텍스트(24px/18.7px 볼드)' 완화 기준(3:1)이 적용되지 않는다 → **4.5:1 필요.** 보조 텍스트는 INK-muted(`#60655C`), 에러는 ERROR(`#DC2626`)로 해결됨. ⚠️ 유일한 예외 GREEN-500(`#788F4A` ~3.5:1)만 텍스트로 쓰지 않는다(면/데코 전용).
  - **초록 텍스트는 무조건 GREEN-700(`#5B6B38`).** GREEN-500(`#788F4A`)을 연초록 패널 위 텍스트로 쓰면 ~2:1로 결함이다.
- **원형 조작(뒤로가기 등)은 항상 면을 갖고, 면 색은 바닥이 정한다.** 새 색을 만들지 말고 canonical 값을 짝으로만 쓴다.
  - 밝은 바닥(초록 밴드·크림 페이지·베이지 시트): **흰 면 `#FFFFFF` + INK 글자 + 옅은 그림자** — 기본값이고 `BackButton` 이 이걸 쓴다(§7).
  - 사진·어두운 바닥(카메라 프리뷰): **INK 면 `#2C3930`/70 + 크림 글자** — 참고 `CameraPage`. 흰 피사체가 뒤에 와도 글자 대비 4.4:1 로 비텍스트 기준(3:1)을 넘긴다.
  - 사진 위에 밝은 면을 얹지 않는다. 화면에서 제일 밝은 덩어리가 돼 피사체보다 먼저 읽힌다.
  - 어두운 면에는 그림자를 달지 않는다(검은 그림자가 안 보인다). 띄우는 건 밝은 면일 때만.
  - 지도 위 헤더(`RouteViewPage`)의 뒤로가기도 **흰 면**이다 — 지도 타일은 밝은 바닥이라 같은 규칙을 따른다. 옆의 제목은 면을 깔지 않고 흰 외곽선으로 읽히게 한다(§7.1).
- **프로필 동결은 풀렸다** — 프로필 재디자인(§8)과 함께 진행 중이다. `ProfilePage` 는 canonical 로 옮겼고, 하위 7개 화면(`ProfileEdit`·`Subscription`·`TravelCalendar`·`Favorites`·`AlertLogs`·`PrivacyPolicy`·`HelpFaq`)에 프로필 전용 색이 남아 있다: `#9CAB84`(§1.2 가 없앤 눈대중 변형) · `#90908F`·`#8D8D8D` → INK-muted · `#303030`·`#111` → INK · `#FF4B4B` → ERROR `#DC2626` · `#ABC582` → GREEN-300.

## 2. 타이포그래피

- **폰트:** `KOROAD` (Light 300 / Medium 500 / Bold 700 face 로딩). 본문 스택 fallback 은 system-ui 계열.
- **크기:** 최소 **13px**, 본문 **15px**. 이 두 값을 기본으로 하고, 더 크거나 중간값은 시안 근거가 있을 때만.
- **굵기:** **regular + medium 만.** 볼드(`font-bold`/700)는 쓰지 않는다.
  - 코드베이스 관행: **400(regular) face 가 없어 `font-normal`/미지정도 500 Medium 으로 렌더**된다. 즉 regular 와 medium 이 사실상 같은 500 로 보인다.
  - de-emphasis(약하게)만 `font-light`(300) 사용.
- **금지:** `text-xs`(12px) 이하 본문, `font-bold`, `font-semibold`(600 face 없어 700 로 폴백됨).
- **예외 없음 — 헤드라인도 medium 이다.** `/premium` 히어로(27px)에 잠깐 `font-bold` 를 뒀다가 되돌렸다. 파는 화면의 헤드라인이라는 근거로 예외를 열어 뒀었는데, **크기만으로도 위계가 서서 볼드가 필요 없었다.** 예외를 하나 열면 "여기도 파는 자리"라는 이유가 계속 생긴다 — 종전 `PremiumPage` 가 카드 제목·표·버튼까지 전부 `font-bold` 였던 게 그 끝이다.

## 3. Safe-area · 노치 (iOS PWA)

`index.html`: `viewport-fit=cover` + `apple-mobile-web-app-status-bar-style: black-translucent`.

- **앱 컬럼(`AppShell`)은 화면 맨 위에서 시작한다 — 노치 아래가 아니다.** 셸도 `body` 도 상단 안전영역을 주지 않는다. 노치 영역은 크림 `:root`(`#FFFCEF`) base 가 채워서 배경은 자연스럽게 이어지지만, **안전영역은 화면 맨 위 요소가 직접 줘야 한다.** 안 주면 제목이 노치 뒤로 들어간다(`AlertLogsPage`·`SubscriptionPage` 가 그랬다).
- **노치까지 full-bleed 가 필요한 요소(지도 등)** 는 컬럼 안 `absolute`/`flex-1` 로는 노치를 못 덮는다(크림이 비쳐 잘려 보임). → **`fixed inset-0 mx-auto sm:max-w-[390px]`** 로 visual viewport 를 덮는다(참고: `MarkerStoryViewer`, `HomePage`/`RouteViewPage` 지도).
- **헤더·배너 상단 여백은 `pt-header` 하나다** (= `--banner-top` = `env(safe-area-inset-top) + 16px`, 홈 배너와 같은 값). 각자 상수를 들지 않는다 — 모으기 전엔 같은 '헤더 상단'이 0·12·16·24px 로 네 갈래였고, 동선 생성 스텝 1↔2 처럼 이어지는 화면 사이에서 뒤로가기가 4px 씩 튀었다. 고정 px(`pt-[68px]` 등)도 금지 — safe-area 가 작은 기기에서 과하게 뜬다.
  - 안전영역을 **헤더 높이에 섞지 않는다.** `h-[calc(env(safe-area-inset-top)+56px)] items-end` 같은 꼴은 다른 화면과 같은 값인지 눈으로 알 수 없다(`BlogDetailPage` 가 그랬다).
  - 예외는 헤더가 아닌 것들이다: 프리미엄 히어로(`+72px`), 사진 위 오버레이(`max(safe-area, …)` — 노치 없는 기기에서도 최소 여백이 필요), 모달·토스트.
- **하단:** 스크롤 페이지 하단 여백 `pb-nav`(탭바+안전영역+24px), 탭바 위 떠 있는 요소 `bottom-nav`, 순수 안전영역 `pb-safe` / `pt-safe`. 고정 px 로 안전영역을 흉내 내지 않는다.

## 4. 레이아웃 셸

- **모바일 풀폭, ≥640px(`sm:`)는 390px 중앙 컬럼**(`sm:max-w-[390px]`). 시안이 390px 모바일 프레임 하나라 데스크톱 레이아웃은 없다.
- **가로 패딩은 셸이 주지 않는다 — 페이지 책임.** 지도처럼 full-bleed 가 필요한 화면이 깨지기 때문. 페이지가 `px-5` 등으로 자체 여백을 준다.
- **하단 탭바는 흐름에서 빼서 콘텐츠 위에 얹는다**(`absolute`, `fixed` 아님 — iOS PWA 뷰포트 quirk 회피). 콘텐츠는 `pb-nav` 로 가림 방지.
- **바텀시트·모달은 `createPortal` 로 body 에 붙되** `fixed inset-x-0 mx-auto sm:max-w-[390px]` 로 같은 컬럼에 정렬.

## 5. 칩 (`shared/components/Chip`)

가로로 늘어놓고 고르는 알약 버튼. **새로 만들지 말고 이걸 쓴다** — 모으기 전엔 네 군데가 모서리(완전 둥금 vs 10px)·높이(28·34·38·40)·글자(14 bold vs 15 medium)·상태 표시가 다 달랐고, 그중 하나는 대비 미달이었다.

공통: `rounded-full`, **15px medium**, `md` 40px(기본·권장 터치 영역) / `sm` 32px(보조 전환에만).

| 톤 | 어디에 | 고름 | 안 고름 |
|---|---|---|---|
| `outline` | 크림·흰·시트 배경 위 주 선택기 | GREEN-700 채움 + 흰 글자 **5.83:1** | 흰 채움 + GREEN-300 테두리 **12.10:1** |
| `ghost` | 보조 전환(정렬 등) | GREEN-300 채움 + INK **7.89:1** | 맨 글자 `#60655C` **5.81:1** |

*(대비는 브라우저 실측값.)*

- **고른 칩에 GREEN-500 금지.** 흰 글자가 3.6:1 이라 §1.2 의 '데코 전용' 규칙에 걸린다.
- **안 고른 칩의 글자를 흐리게 하지 않는다.** 눌러서 고를 수 있는 버튼이라 읽혀야 한다 — 차이는 채움과 테두리로 낸다.
- 짙은 바닥(지도·초록 패널) 위에 크림 칩을 얹는 `cream` 톤이 있었으나, 유일한 사용처였던 동선 시트가 흰 바닥이 되면서 지웠다. 지도 위에 칩을 직접 띄우는 화면이 생기면 되살릴 것.
- 토글이면 `selected`(→ `aria-pressed`), 라디오 그룹이면 `role="radio"` + `aria-checked` 를 직접. 한 번 하고 끝나는 동작(예: 고른 날짜 빼기)이면 `selected` 를 안 넘긴다.
- **바깥 여백·스크롤은 부모 몫.** 칩 줄이 놓이는 방식은 화면마다 다르다.

## 6. 캘린더 (`shared/components/CalendarGrid`)

- **격자는 `shared/components/CalendarGrid` 하나뿐이다.** 달력이 필요하면 새로 그리지 않는다. 달 이동 줄은 `CalendarMonthNav`, 지금 보는 달의 상태는 `shared/hooks/useMonthCursor`.
- **첫 열은 항상 일요일.** 화면마다 다르면 날짜를 잘못 짚는다([#104](https://github.com/PicTree-UMC/PicTree-Frontend/issues/104)).
- **주말 색은 일 `#FF8080` · 토 `#78A3FF`.** 한국 달력 관례를 따르는 **데코 액센트**다 — 날짜는 위치로도 읽히고 색은 거들 뿐이라 본문 대비 기준을 적용하지 않는다.
- **고를 수 없는 날은 회색 `#B4B4B4`, 주말 색을 쓰지 않는다.** 못 누르는 날짜가 제일 튀는 색을 갖는 게 이상하고, 달력의 대비는 '고를 수 있나' 에만 쓴다. 투명도로 흐리지 않는다 — 흐린 빨강은 분홍으로 읽힌다.
- **채움**: 여러 날 고르기는 GREEN-300 원, 기간 고르기의 양 끝은 **GREEN-700**(흰 글자 5.83:1) + 사이 띠는 GREEN-100. 흰 글자를 얹는 자리에 GREEN-500 을 쓰지 않는다(§1.2).
- **바깥 틀(헤더·카드·버튼)은 화면 몫.** 여행 캘린더는 연도 피커가 달린 자체 헤더를 쓰고, 블로그 기간 선택과 동선 날짜 고르기는 `CalendarMonthNav` 를 쓴다.
- 칩과 같은 규칙을 따른다: 고른 칸의 글자를 흐리게 하지 않고, 흰 글자 자리엔 GREEN-700(§5).

## 7. 뒤로가기 (`shared/components/BackButton`)

헤더 맨 앞의 뒤로가기. **새로 만들지 말고 이걸 쓴다.**

- **흰 원 40px · 꺾쇠 6×12 · 획 2.25px · 글리프 INK · 옅은 그림자.** 모으기 전엔 박스가
  24·30·32·36·40px 로 갈렸고, 더 컸던 문제는 **그려지는 꺾쇠**가 9.3×18.7px(프로필) ~
  5.5×11px(블로그) 로 1.7배 차이 났다는 점이다. 박스만 맞춰서는 통일돼 보이지 않는다.
- **면은 항상 있다.** 예전엔 지도·카메라처럼 콘텐츠 위에 뜬 화면에만 원을 줬는데, 그러면 같은
  버튼이 화면마다 다르게 생긴다. 면 색은 바닥이 정한다(§1.2) — 밝은 바닥은 흰 면, 사진 위는 INK 면.
- **꺾쇠는 24 viewBox 를 24px 로** 그린다. 한때 프로필의 12×21 을 기준으로 잡았는데 그건 면이
  없던 시절 얘기다 — 40px 원 안에 넣으면 원을 거의 채운다. 면이 생기면 글리프는 작아져야 한다.
- **바깥 여백은 안 갖는다.** 원의 왼쪽 끝이 헤더 패딩에 그대로 맞는다 → **헤더 가로 패딩은 `px-5`.**
- 종전 아이콘 색 `#303030`(프로필)·`#111`(사진 앨범)은 INK 로 흡수했다(§1.1).
- 같은 자리에서 모드에 따라 다른 글리프(예: 선택 모드의 ×)를 쓸 땐 **같은 40px 흰 원**을 쓴다 —
  모드가 바뀔 때 헤더 첫 칸이 흔들리지 않게(참고: `AlertLogsPage`).

### 7.1 내비게이션 줄 (`shared/components/NavBar`)

뒤로가기 + **가운데 제목** + 오른쪽 액션(선택). 바깥 `<header>`(초록 밴드·sticky·`pt-header`·
아래 부가 행)는 화면 몫이고, 이 컴포넌트는 줄 하나만 그린다.

- **제목은 18px medium, 화면 정가운데.** 모으기 전엔 16·19·20·20px 이 섞여 있었고 볼드도 둘 있었다
  (§2 볼드 금지 위반).
- **가운데 정렬은 `absolute` 로 한다.** `flex-1 text-center` 는 좌우 슬롯 폭이 같을 때만 맞는데,
  오른쪽 액션은 '삭제 아이콘'부터 '전체 선택' 글자까지 폭이 제각각이라 제목이 화면마다 밀린다.
- 긴 제목은 60% 에서 자른다. 제목에 `pointer-events-none` 을 둬 오른쪽 액션의 터치를 안 가로챈다.
- **지도 위 헤더는 `titleOnMap`** 을 준다 → 제목에 `.text-halo`(흰 외곽선)가 붙어 지도 라벨·지형
  위에서도 읽힌다. 카카오맵이 지명에 쓰는 방식이다. **알약 배경을 깔지 않는다** — 알약은 글자
  길이만큼 지도를 사각으로 덮지만 외곽선은 획 주변 몇 px 만 덮는다(참고 `RouteViewPage`).

## 8. 그룹 리스트 (`shared/components/SettingsList`)

설정형 화면의 흰 카드 + 줄 묶음. 프로필과 그 하위 화면이 쓴다. **새로 그리지 말고 이걸 쓴다.**

```tsx
<SettingsList>
  <SettingsRow icon={cardIcon} title="구독 및 결제" value="무료" onClick={...} />
  <SettingsRow icon={alertIcon} title="근처 나무 알림" trailing={<토글 />} />
</SettingsList>
<SettingsFooter>50m 안에 내 나무가 있으면 알려드려요.</SettingsFooter>
```

- **테두리는 1px `#ECECEC` 헤어라인.** 크림 페이지(`#FFFCEF`)와 흰 카드는 밝기 차가 **ΔL\* 1.1**
  밖에 안 난다(iOS 의 회색 배경은 4.4). 배경만으로는 카드가 안 보여서 테두리가 그 일을 대신한다.
  종전의 `border-2 border-[#C5D89D]` 는 이 문제를 색으로 때우고 있었는데, 그러면 카드마다 초록
  상자가 도드라져 **틀이 줄 내용보다 먼저 읽힌다.**
  - ⚠️ 페이지 배경을 어둡게(`#F6F0D7`) 해서 푸는 방법도 있지만 §1.1 의 '페이지 배경 = 크림'
    이 한 화면에서만 깨진다. 크림을 지키고 테두리로 푸는 쪽을 택했다.
- **구분선은 글자 시작점에 맞춰 들여쓴다** — 아이콘 있으면 58px(`px-4` 16 + 타일 30 + `gap-3` 12),
  없으면 16px, 가운데 정렬 동작 줄은 0. 카드 폭 전체를 가로지르면 줄이 아니라 칸으로 쪼개져 보인다.
  이걸 자동으로 맞추려고 `SettingsList` 가 자식의 props 를 읽는다 → **직속 자식은 `SettingsRow` 여야 한다.**
- **아이콘은 34px 풀컬러 3D 렌더를 그대로 얹는다**(`image`). 타일도 색칠도 씌우지 않는다 —
  브랜드색 타일에 단색 글리프를 마스크로 칠하는 모드가 잠깐 있었지만, 줄 여섯 개가 전부 3D
  아이콘을 받으면서 지웠다.
  - **배경이 비는 PNG 가 낫다.** 지금은 두 가지가 섞여 있다 — 흰 배경이 구워진 JPG 4개와
    투명 PNG 2개. JPG 쪽이 지금 안 티나는 건 순전히 카드가 흰색이기 때문이라, ⚠️ **카드
    바탕색을 바꾸면 그 4개에 네모난 흰 자국이 드러난다.** 새로 받을 땐 투명 PNG 로 받는다.
  - **넣기 전에 여백을 깎아 정사각으로 다시 채운다.** 원본은 그림이 프레임을 차지하는
    비율이 제각각이라(나무는 꽉 차고 하트는 55%) 같은 상자에 넣으면 무게가 달라 보인다.
    아이콘이 여러 세트에서 오면 더 벌어진다. 내용 경계를 찾아 정사각으로 넓히고 **여백 8%**
    를 붙인다. 경계는 흰 배경이면 밝기(<235), 투명 PNG 면 **알파(>16)** 로 찾는다 —
    투명 배경은 밝기로 안 잡힌다.
  - **크기는 표시의 3배(102px)까지, 원본보다 키우지 않는다.** 폰은 @3x 가 최대라 34px 상자에
    102px 이면 제일 또렷한 기기에서도 충분하다. 100px 짜리를 136px 로 늘렸더니 없던 화질은
    안 생기고 용량만 **17KB → 10KB 차이**로 붙었다. 1024px 원본은 반대로 그대로 넣으면
    개당 25KB 인데 줄이면 ~4KB 다.
  - **읽기만 하는 문서 줄(약관·FAQ)에는 아이콘을 달지 않는다.** 달면 '계정에서 하는 일' 과 같은
    무게로 읽힌다. 한 카드 안에서는 있거나 없거나로 통일한다.
  - 3D 아이콘이 들여오는 빨강·파랑은 팔레트 밖이지만 **일러스트라 UI 색 규칙을 적용하지 않는다**
    (§1 은 면과 글자의 규칙이다). 다만 아이콘끼리는 같은 3D 스타일로 통일한다.
- **부제를 달지 않는다.** 상태는 오른쪽 `value` 로 말하고(`구독 및 결제 — 무료`), 한 줄로 안 되는
  안내는 **`SettingsFooter`** 로 카드 밖에 내린다. 줄마다 두 줄 설명이 붙으면 카드가 아니라 목록처럼
  읽히고 줄 높이가 카드마다 들쭉날쭉해진다.
- **줄 높이 52px.** 권장 터치 영역 44px 에 타일(30px)이 답답하지 않을 만큼만 얹은 값이다.
- **제목 17px medium / 값 15px INK-muted / 화살표 `#B4B4B4`.** 화살표 기하는 `BackButton` 과 같은
  24 viewBox 를 쓴다(§7).
- **섹션 제목(`알림`·`계정`·`정보`)은 두지 않는다.** 카드 사이 간격(`gap-6`)만으로 묶음이 읽힌다.
- **그 자리에서 실행되는 동작은 `action`** — 가운데 정렬 + 화살표 없음. 색이 위험도를 말한다:
  `danger`(ERROR, 로그아웃) / `quiet`(INK-muted, 회원탈퇴). **되돌릴 수 없는 쪽을 더 빨갛게 하지
  않는다** — 나란히 같은 빨강이면 동급으로 읽히고 오탭 위험이 생긴다.
